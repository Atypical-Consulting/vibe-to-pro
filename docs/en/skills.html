Commands & Skills: Industrializing Your Prompts

From an improvised prompt to a versioned procedure

Vibe-coding means retyping the same prompt from memory, with all the variation that implies. A skill freezes that prompt into a versioned SKILL.md file: reproducible, shareable via git, auditable through its allowed-tools.

✗ Not quite. It's .claude/skills/nom/SKILL.md: the successor mechanism to slash commands, which can bundle supporting files.

That prompt you keep retyping: what if it became a file?

How many times have you retyped, almost word for word, the same twenty-line prompt to kick off a code review or generate a changelog? Vibe-coding works exactly like that: you improvise every time, hoping to land on the phrasing that worked well last week. The real problem isn't laziness, it's variability: one forgotten instruction, one missing example, and the result changes without you understanding why. A command or a skill solves exactly this problem: it freezes the prompt once and for all into a file, which you replay identically every time you type the corresponding command.

Concretely, this file can take two forms, and it's worth knowing which one descends from which. The first, historical form is a simple Markdown file placed in .claude/commands/: it remains fully supported today, and it's enough for a simple need. The second, Skills (a .claude/skills/nom/ folder containing a SKILL.md), is the recommended successor mechanism, able to bundle supporting files (scripts, reference docs) alongside the prompt itself. The two have since been merged: a .claude/commands/deploy.md and a .claude/skills/deploy/SKILL.md both create the same /deploy command and work the same way. Migrating to SKILL.md is therefore never a breaking change, just a gain in capability.

But what really turns a frozen prompt into a team tool are the settings you can attach to it in its header. This header, called frontmatter, describes how the skill should run, ahead of the prompt text itself. The disallowed-tools field removes certain tools from the available pool for the whole duration of the skill: useful, for example, to prevent a question asked to the user in the middle of an autonomous loop, where no one is around to answer it. The context: fork field goes further: it runs the skill as an isolated sub-agent, without access to the current conversation's history. This mode now runs in the background by default, so you keep working while the skill acts on its own. Add to that the paths field, which limits a skill's automatic triggering to certain files via glob patterns, and you get a prompt that is no longer just reproducible: it becomes auditable and predictable in its scope of action.

These are the real gains over copy-pasting a prompt: fine control over what a procedure is allowed to do, when it triggers, and how visible it is to you. Once you have these settings in mind, a skill is no longer just a handy shortcut: it's a team procedure you can version, review, and evolve like any other file in the repo. Here, in detail, is what that actually changes.

Hands-on exercise

Create .claude/skills/resume-diff/SKILL.md with minimal frontmatter (description, disable-model-invocation: true) and a body that injects the following command and then asks for a 3-bullet summary:

!git diff HEAD

Test it with /resume-diff, then add context: fork and agent: Explore to run it as a background sub-agent.

Solution & verification

Creating .claude/skills/resume-diff/SKILL.md is enough to make /resume-diff exist. Since slash commands and Skills were merged, a SKILL.md file in .claude/skills/nom/ indeed creates the same /nom command as a plain .claude/commands/nom.md, with the added ability to bundle supporting files.

Adding context: fork and agent: Explore to the frontmatter then makes the skill run as an isolated sub-agent, with no access to the conversation history, executed by an Explore-type agent. Since this fork mode now runs in the background by default, you get control back immediately while the diff summary is generated, unless you add background: false to return to blocking execution.

  • After creating the file, /resume-diff appears in the slash command autocomplete menu without restarting Claude Code.
  • Once context: fork and agent: Explore are added, running /resume-diff hands control back to the prompt right away and the task shows up in /tasks as a background run, instead of blocking the prompt.
  • The generated summary fits in exactly 3 bullets about the files actually changed in git diff HEAD, with no reference to earlier exchanges in the session, which proves the sub-agent runs isolated, without history.
