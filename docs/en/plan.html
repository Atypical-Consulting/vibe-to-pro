Plan Mode & Extended Thinking

Think before acting, tune the depth

In vibe-coding, you hope it works without visibility into what the AI is about to do. Plan mode forces a research phase before any modification, and the effort level makes the model's reasoning explicit and tunable. That's the foundation of a reproducible practice.

What if Claude thought before acting?

You've probably felt this before: you ask Claude Code for a change, and a few seconds later, files have already changed. The result sometimes works, but you discover the logic after the fact, once the action is already done. That's the classic vibe-coding reflex, where you hope it works without seeing the decision coming. Plan mode reverses that order: before touching a single file, Claude explores the existing code, thinks through an approach, then submits a plan to you. Nothing is modified until you've approved that plan.

How do you switch into this mode? Two ways: typing /plan (with or without a description of the topic) or pressing the Shift+Tab shortcut. Either way, the switch is immediate, with no confirmation prompt beforehand. Once inside, Claude can read files and run read-only commands to explore your project, but can't write anything. And since a recent update, these read commands no longer even trigger confirmation one by one: an auto mode classifier evaluates them on the fly during planning, a behavior controlled by the useAutoModeDuringPlan setting (on by default). The idea: reading carries no risk, only writing should require your explicit go-ahead.

But thinking before acting isn't limited to the structure of plan mode: reasoning depth is also tunable. Add the word "ultrathink" anywhere in your message, and Claude devotes more internal reasoning to that specific turn, without touching the session's overall setting, a kind of one-off spotlight. Watch out if you learned Claude Code more than a year ago: the old keywords "think", "think hard", or "think more" are no longer recognized as special today, they're passed through as ordinary text and so no longer have any effect on reasoning. For a setting that lasts the whole session rather than a single turn, the /effort command opens a five-level selector (low, medium, high, xhigh, max), useful for switching to xhigh on a complex design problem then dropping back to low for simple, cheaper tasks.

This reasoning dial can also be turned on continuously, for the whole session, via the Option+T shortcut (or Alt+T on Windows/Linux). The /config command can also make this setting permanent. Good news if you delegate work to a subagent: it automatically inherits the main conversation's extended thinking setting, with nothing to reconfigure on each delegation. And the plans themselves don't vanish into thin air: the plansDirectory setting chooses where Claude Code writes these plan files, for example so you can version them in the repo and review them in code review. Here, in detail, is what this changes concretely in your day-to-day practice.

Hands-on exercise

Run the following command:

claude --permission-mode plan

Then ask: "ultrathink: propose an architecture for adding rate limiting to this API". Watch the plan, approve it with "Yes, and use auto mode". In a new session, compare /effort low vs /effort xhigh on the same question to feel the difference in depth.

Solution & verification

The keyword "ultrathink" is today the only recognized trigger for a one-off, deeper reasoning pass, on a single turn, without changing the session's effort level. That's what pushes Claude to produce a more thoroughly argued rate-limiting plan before you've even approved anything. Once that plan is approved via "Yes, and use auto mode", comparing /effort low vs /effort xhigh then cleanly isolates the depth variable: /effort opens a 5-level selector (low, medium, high, xhigh, max). Running the same question under each of these two settings, in two separate sessions, lets you feel the difference in reasoning without an "ultrathink" effect or conversation history skewing the comparison.

  • As long as you haven't responded to the end-of-plan prompt, no modification command runs: the prompt stays in plan mode and offers options like "Yes, and use auto mode" rather than acting directly.
  • After choosing "Yes, and use auto mode", subsequent tool calls run without a per-command confirmation popup, a sign that the session has indeed switched to auto mode for the rest of the work.
  • In each of the two new sessions, /effort alone (with no argument) shows the active level (low, then xhigh); the plan produced under xhigh should be noticeably more developed (more steps, more justification for architecture choices) than the one produced under low, confirming that the setting did change the reasoning depth.
