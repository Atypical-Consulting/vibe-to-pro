00 · The problem

A prompt that works isn't a practice.

Vibe-coding produces results, but no guarantees: no permission scope, no trail, no safety net if something breaks. Here is the same intent, handled two ways.

vibe-coding
$ claude
> fix the login bug
...4 files changed, no review
✓ "looks like it works"
✗ pushed straight to main
pro practice
$ claude --permission-mode plan
> fix the login bug
→ plan proposed · 3 files · 2 tests
✓ /code-review high --fix
✓ /commit-push-pr → PR #142
01 · The method

Nothing is taught without being verified.

This course isn't written from memory. Every fact follows the same pipeline before becoming a line in the course:

1

Extract

All 385 versions of the official CHANGELOG are split up and reviewed to isolate the major features, not the minor fixes.

2

Verify

Each candidate feature is checked, independently, against current documentation on code.claude.com through a dedicated search.

3

Decide

Every fact gets a verdict: confirmed, updated (behavior has changed since), or unverifiable.

4

Discard or publish

Only confirmed or updated facts make it into the course, source cited. Everything else is discarded, never presented as settled.
