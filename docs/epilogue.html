Épilogue : checklist du praticien & sources

Douze leviers, un seul objectif : ne plus jamais avoir à espérer. Voici la checklist qui résume ce cours. Cochez‑la avant de dire qu'un projet Claude Code est « prêt pour la prod ».

Exercice pratique

Reprenez votre dépôt d'entraînement du module 01 et combinez trois leviers déjà pratiqués dans une seule configuration cohérente : (1) le sandbox actif avec une règle sandbox.credentials.files (module Contrôle & sécurité), (2) un hook PreToolUse qui bloque rm sans confirmation (module Hooks), (3) une session ouverte dans un claude --worktree isolé (module Git & worktrees). Lancez une session dans ce worktree et vérifiez que les trois protections restent actives simultanément : c'est exactement la configuration .claude/ que la checklist ci‑dessous décrit, pas trois réglages isolés testés un par un.

Checklist du praticien pro

  • Le sandbox Bash et les règles réseau sont actifs sur tout projet touchant des secrets ou une prod.
  • .claude/settings.json (permissions, hooks) est versionné et revu comme du code.
  • CLAUDE.md documente les pièges et conventions non standard, pas ce que Claude peut déjà déduire du code.
  • Les tâches répétées vivent dans des skills versionnées, pas dans la mémoire de qui tape le prompt.
  • Les tâches risquées passent par le mode plan avant toute exécution.
  • Les sous‑agents ont un périmètre d'outils explicite (tools:/disallowedTools:), pas un accès total par défaut.
  • Les vérifications critiques (lint, tests, secrets) sont des hooks, pas des espoirs.
  • Chaque serveur MCP externe est passé en revue avant approbation, avec une allowlist en équipe.
  • /rewind et les worktrees sont réflexes avant toute expérimentation risquée sur du code partagé.
  • Les workflows multi‑agents ont une workflowSizeGuideline assumée, pas « laisser tourner et voir ».
  • Les plugins installés sont épinglés par SHA et leur coût en tokens est connu (claude plugin details).
  • Les intégrations CI utilisent --bare, une sortie --output-format json et des permissions explicites, jamais un --dangerously-skip-permissions dans un pipeline partagé.

Quiz de synthèse

Quiz éclair · controle

Que fait précisément le flag --restricted, par rapport à une session en mode bypass ?

✓ Exact. Exact. --restricted retire les outils d'exécution de commandes et WebFetch, confine les outils fichiers au répertoire de travail, et refuse le mode bypass ; ce choix ne peut pas être annulé en cours de session. À réserver à l'ouverture d'un dépôt non fiable ou à l'expérimentation d'un débutant sans risque d'évasion de sandbox.
✗ Pas tout à fait. Pas tout à fait : --restricted va plus loin qu'une simple coupure réseau ou qu'un mode manual classique : il retire aussi les outils d'exécution de commandes et WebFetch, confine les fichiers au répertoire de travail, et interdit tout retour au mode bypass pendant la session.
Quiz éclair · memoire

Comment empêcher qu'un chemin @chemin/vers/fichier.md soit importé automatiquement dans CLAUDE.md ?

✓ Exact. Exact. Entourer un chemin de backticks (@README) empêche son import automatique ; sans backticks, un chemin @chemin/vers/fichier.md est bien importé, avec une profondeur maximale de 4 sauts.
✗ Pas tout à fait. Pas exactement. C'est l'usage des backticks autour du chemin (@README) qui bloque l'import : les commentaires HTML et la profondeur des sauts n'ont pas ce rôle.
Quiz éclair · skills

Que fait le champ disallowed-tools dans le frontmatter d'un SKILL.md ?

✓ Exact. Exact. disallowed-tools réduit le pool d'outils disponible pendant l'exécution de la skill. C'est utile par exemple pour empêcher AskUserQuestion dans une boucle autonome où personne ne peut répondre à une question.
✗ Pas tout à fait. C'est disallowed-tools qui retire, pour la durée de la skill, des outils du pool disponible, typiquement pour empêcher AskUserQuestion dans une boucle autonome.
Quiz éclair · plan

Dans les settings.json de Claude Code, quel paramètre détermine où le mode plan écrit ses fichiers de plan ?

✓ Exact. Exact. Le paramètre plansDirectory choisit où le mode plan écrit ses fichiers de plan, et il est résolu relativement à la racine du projet, ce qui est utile par exemple pour versionner ces plans dans le dépôt et les relire en revue de PR.
✗ Pas tout à fait. Pas tout à fait. C'est plansDirectory, résolu relativement à la racine du projet, pratique pour versionner les plans générés et les relire en revue.
Quiz éclair · agents

Par défaut, combien de sous-agents Claude Code peut-il exécuter en parallèle dans une session ?

✓ Exact. Exact. Le plafond par défaut est de 20 sous-agents concurrents, ajustable via la variable d'environnement CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS ; le plafond total par session, lui, a été supprimé en v2.1.224.
✗ Pas tout à fait. Pas tout à fait. Le plafond par défaut est en réalité de 20 sous-agents concurrents, ajustable via CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS.
Quiz éclair · hooks

D'après la documentation des hooks, quel événement se déclenche juste avant une compaction du contexte et peut la bloquer avec un code de sortie 2 ?

✓ Exact. PreCompact se déclenche juste avant une compaction et peut la bloquer (code de sortie 2). PostCompact, lui, se déclenche seulement juste après, ce qui est utile par exemple pour archiver des informations importantes avant qu'elles ne soient compactées.
✗ Pas tout à fait. C'est PreCompact : il intervient avant la compaction et peut la bloquer avec un code de sortie 2. PostCompact se déclenche après coup, une fois la compaction déjà effectuée, donc trop tard pour l'empêcher.
Quiz éclair · mcp

Quel type de transport MCP est aujourd'hui recommandé pour un nouveau serveur, d'après la documentation ?

✓ Exact. Exact. Le transport HTTP streamable est recommandé partout où c'est possible ; SSE reste supporté mais est explicitement marqué déprécié dans la documentation.
✗ Pas tout à fait. Pas tout à fait. C'est le HTTP streamable qui est recommandé : SSE reste supporté, mais il est marqué comme déprécié.
Quiz éclair · rewind

Que fait précisément l'option « Summarize up to here » du menu /rewind ?

✓ Exact. Exact. « Summarize up to here » agit uniquement sur l'historique de conversation : elle le compresse avant le point choisi, sans modifier les fichiers sur disque. C'est utile pour libérer du contexte sans perdre le travail de code déjà effectué.
✗ Pas tout à fait. Pas tout à fait. Cette option ne touche à aucun fichier et ne crée aucun commit : elle compresse seulement la conversation avant le point choisi, en laissant le code intact.
Quiz éclair · git

Sans configuration particulière, depuis quelle référence un nouveau worktree Claude Code démarre-t-il par défaut ?

✓ Exact. Exact. worktree.baseRef vaut "fresh" par défaut depuis la v2.1.133 : chaque nouveau worktree part d'origin/<branche par défaut>. Le réglage "head" (à activer explicitement) part de votre HEAD local, commits non poussés compris.
✗ Pas tout à fait. Pas tout à fait. Le défaut est "fresh" : il part d'origin/<branche par défaut>. "head" existe aussi, mais c'est une option qu'il faut activer soi-même pour partir de son HEAD local avec les commits non poussés.
Quiz éclair · echelle

Quel est le plafond de tâches récurrentes que les outils CronCreate/CronList/CronDelete peuvent planifier par session ?

✓ Exact. Exact. Le plafond est de 50 tâches récurrentes par session pour les outils CronCreate/CronList/CronDelete ; /loop, de son côté, exécute un prompt ou une skill à intervalle régulier directement dans la conversation en cours, sans ce plafond.
✗ Pas tout à fait. Pas tout à fait. C'est 50 : les outils Cron (CronCreate/CronList/CronDelete) plafonnent à ce nombre les tâches récurrentes planifiées par session, à distinguer de /loop qui tourne dans la conversation courante.
Quiz éclair · plugins

Pour une source de plugin github/url/git-subdir, quel champ de marketplace.json épingle une version exacte du plugin, indépendamment des futurs commits sur la branche ?

✓ Exact. Exact. Le champ sha (un commit git complet) épingle une version précise du plugin, insensible aux commits ultérieurs poussés sur la branche référencée.
✗ Pas tout à fait. Pas tout à fait. C'est le champ sha (un commit git complet) qui épingle une version exacte, indépendamment des futurs commits sur la branche. Il n'existe ni champ version ni champ tag pour cet usage.
Quiz éclair · infra

Dans quel cas le mécanisme fallbackModel du SDK ne bascule-t-il jamais sur un modèle de secours ?

✓ Exact. Exact. fallbackModel accepte jusqu'à trois modèles essayés dans l'ordre, mais uniquement en cas de surcharge ou d'erreur serveur, jamais pour une erreur d'authentification, de facturation ou de rate-limit.
✗ Pas tout à fait. Pas tout à fait. La surcharge et l'erreur serveur déclenchent bien un basculement ; c'est justement l'erreur d'authentification, de facturation ou de rate-limit qui n'active jamais fallbackModel.
