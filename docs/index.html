00 — Le constat

Un prompt qui marche n'est pas une pratique.

Le vibe‑coding produit des résultats, mais aucune garantie : pas de périmètre de permissions, pas de trace, pas de filet en cas d'erreur. Voici la même intention, traitée deux façons.

vibe‑coding
$ claude
> corrige le bug de login
…4 fichiers modifiés, aucune review
✓ « ça a l'air de marcher »
✗ push direct sur main
pratique pro
$ claude --permission-mode plan
> corrige le bug de login
→ plan proposé · 3 fichiers · 2 tests
✓ /code-review high --fix
✓ /commit-push-pr → PR #142
01 — La méthode

Rien n'est enseigné sans être vérifié.

Ce cours n'est pas écrit de mémoire. Chaque fait suit le même circuit avant de devenir une ligne du cours :

1

Extraire

Les 385 versions du CHANGELOG officiel sont découpées et passées en revue pour en isoler les fonctionnalités majeures — pas les correctifs mineurs.

2

Vérifier

Chaque fonctionnalité candidate est confrontée, indépendamment, à la documentation actuelle sur code.claude.com par une recherche dédiée.

3

Trancher

Chaque fait reçoit un verdict : confirmé, mis à jour (le comportement a changé depuis), ou non vérifiable.

4

Écarter ou publier

Seuls les faits confirmés ou mis à jour entrent dans le cours, source citée. Le reste est écarté — jamais présenté comme acquis.
