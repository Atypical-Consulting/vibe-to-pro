方法论

本课程如何核实它教给你的每一条事实。

本课程不是凭记忆写成的。它从 Claude Code 的 官方 CHANGELOG 出发，让每一项候选功能都先走完一套核实流程，然后才会成为课程中的一行内容。

385个 changelog 版本已分析
395项候选功能已核实
371项已确认或已更新
98项收入 14 个模块

核实流程

1

提取

385 个 CHANGELOG 版本（从 0.2.21 到 2.1.260）被逐条拆解和审阅，从中筛出重要功能，而不是小修复或内部改动。

2

核实

395 项候选功能中的每一项，都会独立地与 code.claude.com 上的当前文档比对，比对通过专门的检索完成，绝不依赖模型的记忆。

3

分类

每条事实都会得到一个结论：已确认 共 316 项，此后未发生变化；已更新 共 55 项，行为在该 changelog 版本之后有所变化；或 无法核实 共 24 项，已剔除。

4

筛选

在 371 条已确认或已更新的事实中，有 98 条收入课程的 14 个模块。它们是按教学价值挑选出来的，也是为了让每个模块保持可读，而不是因为其余的都是错的。

被剔除的部分

有 24 项候选功能无法与当前文档核对一致：写法不同、页面已下线、行为变了却没有清晰记录。它们不会出现在课程的任何地方，而不是被当作既定事实呈现出来。

查看 24 条被剔除事实中的 3 个真实例子
  • 无法核实「命令 /approved-tools」 (v0.2.26)：历史 changelog 提到过它，但当前没有任何页面为它提供文档；它似乎在后来的某个阶段被改名为 /permissions (但两者之间的关联没有得到直接确认)。
  • 无法核实「子代理在权限被拒绝后仍会继续工作，尝试另一种替代方案」 (v2.1.0)：这个说法合理，也符合通用的智能体工作方式，但没有任何官方来源描述过这一具体行为。
  • 无法核实「Agent 工具的返回结果包含 token 数量、工具调用次数和耗时」 (v2.1.30)：没有任何工具参考页面明确提到输出中包含这三项指标。

已知的局限

核实工作基于某一时点的公开文档（2026 年 9 月 2 日，Claude Code v2.1.260）。Claude Code 每周都会发布多个新版本，所以今天准确的细节明天可能就变了。课程中的每条事实都标注了核实日期：在生产环境中依赖它之前，请始终用 claude --version 和当时生效的文档再确认一次。
