插件 & 市场

为整个团队配备工具，而不只是为自己

Vibe Coding 时，随手找到一个插件就装上，然后祈祷它能用。专业做法里，插件和市场带来可复现性（用 SHA 锁定版本）、安全性（密钥绝不注入 shell）以及治理能力（显式启用，token 成本可见）。

水平测试

✓ 正确。即使插件已经安装，也仍然需要显式启用：这是一道防止静默启用的保护。
→ 您已经掌握这个手段，直接进入下一个模块
✗ 不完全正确。需要运行 claude plugin enable <name>：光安装还不够，该插件被标记为 defaultEnabled: false.

在 GitHub 上找到一个插件，你把它装上了……然后呢？

插件很诱人：别人写好了，你装上，Claude Code 突然就多会一件事。在 Vibe Coding 里，这往往就是全部诉求。能跑就行，继续。但插件不只是多一条命令：它还能带来代理、hooks（在特定时刻自动触发的脚本），甚至整套 MCP 或 LSP 服务器（LSP 即 Language Server Protocol，让编辑器深入理解某种编程语言的协议），这一切都被打包，并通过一个 市场 分发出去，它相当于一份共享目录。对团队来说，有意思的地方正在这里：只要在 .claude/settings.json 中通过 extraKnownMarketplaces 声明这个市场一次，所有人就都能用上，无需各自重新安装。

但安装插件并不等于启用它，这是一个有意为之的设计选择。如果作者设置了 defaultEnabled: false，写在 plugin.json 里，那么在你自己运行 claude plugin enable <name> 之前，插件始终处于停用状态。为什么要多这一步、看起来像是多余的？因为一个安装即自动启用的插件，会在你决定信任它之前就作用于你的项目。而在迈出这一步之前，你可以先查询 claude plugin details <name>：这条命令会列出插件包含的内容，并预估它给每次会话增加的 token 成本。这样你在启用之前就知道自己启用的是什么，而不是启用之后才知道。

还剩一个经典问题：指向某个 GitHub 分支的插件可能在你脚下悄悄改变，下周推送的 commit 已经不是你今天测试的那个。正因如此，marketplace.json 可以锁定一个 sha，即一个完整的 git commit，像一张定格的照片，而不是持续流动的画面。插件根本不在 git 上时，逻辑也一样：一个 archive 类型的源可以直接通过 HTTPS 安装一个 zip，不需要 git 也不需要 npm，同样带有可选的 SHA-256 哈希，用于确保收到的内容正是预期的内容。结果就是：你测试过的东西，精确到 commit，就是同事机器上或 CI 里运行的东西。

还有配置与安全方面的信任问题。一个克隆下来的仓库能不能悄悄把自己的插件配置塞进你的会话？不能：pluginConfigs 已不再从 项目 级 settings 中读取，只有你的用户级 settings、--settings 或组织托管的 settings 才算数。写入它们的是 /plugin 命令，写进你自己的 ~/.claude/settings.json。插件的 hooks 同样需要警惕：${user_config.*} 的 shell 形式替换会被阻止，因为一旦某个配置值包含恶意代码，它就会打开一个注入漏洞；必须改用 exec 形式，或者读取环境变量 $CLAUDE_PLUGIN_OPTION_<KEY>。下面就具体看看这带来了什么变化。

实践练习

运行下面这条命令：

claude plugin init my-plugin --with skills hooks

把 "defaultEnabled": false 加入生成的 plugin.json，然后确认必须运行下面这条命令才能启用它：

claude plugin enable my-plugin

最后执行这条命令，查看它每次会话的预估 token 成本：

claude plugin details my-plugin
解答 & 验证

claude plugin init 生成的 plugin.json 自身不会启用任何东西。一旦你在其中加入 "defaultEnabled": false，插件参考文档就要求：插件即使已经安装，也必须显式启用才会生效。这正是为什么 claude plugin enable my-plugin 成为一个必需步骤，而不是可选步骤。插件启用之后，claude plugin details my-plugin 会列出它声明的组件（这里是通过 --with skills hooks 请求的 skills 和 hooks），并在你真正用到它们之前就预估它们每次会话的 token 成本，从而让你不必盲目运行插件也能判断它的占用。

  • 在执行 claude plugin enable 之前，会话中调用该插件的命令或 skill 会失败或根本看不到，而 claude plugin list（或 REPL 中的 /plugin）会显示 my-plugin 处于已禁用状态。
  • claude plugin enable my-plugin 以退出码 0 结束，并使 my-plugin 在 claude plugin list 中变为已启用状态。
  • claude plugin details my-plugin 除了列出声明的 skills 和 hooks，还会显示每次会话 token 成本的量化估计（一个数值），而不只是组件名称。
