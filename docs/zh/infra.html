SDK、无头模式、CI/CD & IDE

让 Claude Code 成为一块基础设施构件

Vibe Coding 在交互模式下凭直觉逐个确认每个操作：这无法规模化。无头模式和 SDK 把 Claude Code 变成可复现的基础构件：确定性的脚本、明确的护栏、可在 CI 中直接使用的结构化输出。

水平测试

哪个标志会跳过对 hooks、skills、子代理、插件、MCP 和 CLAUDE.md 的自动发现？

✓ 正确。这是所有脚本化调用或 SDK 调用的推荐模式：行为可预测，不受隐式本地配置影响。
→ 你已经掌握这一环，可以直接进入下一个模块
✗ 不完全正确。答案是 --bare：它消除对本地配置的一切自动发现，让脚本化行为可预测。

如果没有人在场点击「是」呢？

在交互模式下，一切都很简单：你能看到 Claude Code 即将做什么，随时确认或纠正。但如果你想把 Claude Code 接入一条 CI/CD 流水线（每次推送都会自动构建并测试你代码的系统），而它在凌晨 3 点运行，屏幕前空无一人，会发生什么？又或者你想从自己的程序里像调用一个普通函数那样调用它呢？此时交互模式连同它的确认提示和隐式本地配置就不再合适：你需要一种每次执行都完全相同的行为，没有意外，也不依赖你机器上残留的东西。

这正是无头模式（没有界面，完全由命令行驱动）和以下标志的用武之地：--bare. --bare 会彻底清空一切：它跳过对 hooks、skills、子代理、插件、MCP 服务器、记忆以及 CLAUDE.md文件的所有自动发现。结果是：只有你在命令行上显式传入的内容才决定本次会话的行为，这让它在不同机器之间可复现。再结合 --permission-prompts none，它会自动把任何本来会触发确认提示的操作转为拒绝，于是你得到一个永远不会卡住、不会苦等一个不会到来的人工回应的脚本。SDK（如今更名为 Claude Agent SDK）在代码一侧确立了同样的逻辑：你的程序不再需要敲命令，而是直接驱动一个 Claude Code 会话。

但无人监督的脚本还必须懂得替你自我保护。SDK 的 canUseTool 回调很好地体现了这种分层思路：只有当排在它前面的环节（一个 PreToolUsehook、一条 allow/deny/ask 规则、权限模式）都没有做出裁决时，它才会被调用，这让你可以在不重复已有机制的前提下加入定制的业务校验。在韧性方面同样谨慎：fallbackModel 机制会在服务器过载或出错时自动切换到备用模型，但绝不会因为认证、计费或速率限制错误而切换。换模型解决不了这类问题：与其掩盖一次真正的故障，不如让任务明确失败。至于 maxBudgetUsd，它为一次自动化执行的花费设定上限：没有人实时盯着计数器，所以只能由这个参数自己在账单失控前切断。

还剩最后一个问题：没有人盯着屏幕，流水线怎么知道一切正常？靠产出结构化输出，而不是需要肉眼解读的文本。在 --output-format stream-json下，system/init 消息就暴露了一个 plugin_errors 字段，它列出插件加载错误（没有错误时该字段不存在），这为 CI 脚本提供了一道容易编写的校验关口。至于在键盘前工作而非在流水线里，同一个 CLI 也集成进了 VS Code 扩展（侧边栏、内联 diff、与选区关联的 @ 提及），而 /statusline 则实时告诉你正在使用的模型、成本和上下文。下面详细说明这些具体带来了什么改变。

快速测验

SDK 的 fallbackModel 机制在什么情况下绝不会切换到备用模型？

✓ 正确。正确。fallbackModel 最多接受三个模型并按顺序尝试，但仅限服务器过载或服务器出错的情况，绝不用于认证、计费或速率限制错误。
✗ 不完全正确。不完全正确。过载和服务器错误确实会触发切换；恰恰是认证、计费或速率限制错误永远不会启用 fallbackModel。
快速测验

在 --output-format stream-json 下，system/init 消息中缺少 plugin_errors 字段意味着什么？

✓ 正确。正确。plugin_errors 列出插件加载错误，没有错误时就不会出现，因此可以设置一道简单的 CI 校验关口，例如 jq -e '.plugin_errors // [] | length == 0'。
✗ 不完全正确。不完全正确。这个字段既不说明安装了多少插件，也与 --bare 无关：它的缺失只表示没有发生任何插件加载错误。
实践练习

写出下面这条命令：

claude --bare -p "总结最近 3 个 commit" --allowedTools "Bash(git log *)" --permission-mode auto --permission-prompts none --output-format json

用 jq 检查输出，提取 .result 和 .total_cost_usd.

解答 & 验证

这条命令之所以有效，是因为 --bare 消除了对 hooks、skills、子代理、插件、MCP、记忆和 CLAUDE.md 的一切自动发现：只有在命令行上显式传入的内容（这里是 --allowedTools "Bash(git log *)"）才决定其行为，这让该调用对脚本而言可复现。再结合 --permission-prompts none，它会自动把任何本来会触发确认提示的操作转为拒绝，任务自始至终保持非交互：任何超出 git log 范围的命令都会被直接拒绝，不会等待人工回应。--output-format json 随后会产生单个 JSON 对象，jq 从中提取 .result （摘要）和 .total_cost_usd （本次调用的成本）。

  • 命令以退出码 0 结束，并在 stdout 上输出单个 JSON 对象（不是多行，因为格式不是 stream-json）。
  • jq -r '.result' 返回一段非空文本，确实总结了最近 3 个 commit；而 jq '.total_cost_usd' 返回一个正的小数（绝不为 null）。
  • 执行过程中不会出现任何确认提示；如果尝试了超出 Bash(git log *) 范围的命令，它会被自动拒绝，而不是让终端卡住等待确认。
