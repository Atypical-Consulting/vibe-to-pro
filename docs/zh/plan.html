04

计划模式 & 扩展推理

先思考再行动，并调节推理深度

在 Vibe Coding 中，你只能寄希望于它能跑通，却看不见 AI 究竟会做什么。计划模式强制在任何修改之前先完成一轮调研，而努力级别让模型的推理变得显式且可调节。这是可复现实践的基础。

水平测试

以下哪个关键词至今仍能为单个回合触发更深入的推理？

✓ 正确。如今只有「ultrathink」仍被识别为特殊关键词。「think」「think hard」和「think more」都会被当作普通文本传递。对于一年多以前学习 Claude Code 的人来说，这是一个典型的陷阱。
→ 你已经掌握了这个手段，直接进入下一个模块
✗ 不完全正确。答案是「ultrathink」：其他历史关键词都不再被识别为特殊关键词。

如果 Claude 先思考再行动呢？

你一定熟悉这种感觉：你让 Claude Code 做一处修改，几秒钟之后，文件已经变了。结果有时能用，但你是在动作已经落地之后才发现它的逻辑。这正是 Vibe Coding 的典型反射：只能寄希望于它能跑通，而完全没有预见到那个决策。计划模式把顺序反了过来：在动任何一个文件之前，Claude 先探索现有代码，思考一种方案，然后把计划交给你。只要你没有对这个计划表示同意，就不会有任何东西被修改。

如何切换到这个模式？有两种方式：输入 /plan （可带或不带主题描述），或者按下快捷键 Shift+Tab。两种方式都会立即切换，事先不会有确认提示。进入之后，Claude 可以读取文件、运行只读命令来探索你的项目，但不能写入任何内容。而且从最近的一次演进开始，这些读取命令甚至不再逐条触发确认：auto 模式的分类器会在规划过程中即时评估它们，这一行为由设置项 useAutoModeDuringPlan （默认开启）控制。道理很简单：读取没有任何风险，只有写入才必须经过你的明确放行。

但先思考再行动不止于计划模式的结构：推理的深度同样可以调节。在消息中的任意位置加上「ultrathink」这个词，Claude 就会在这一个回合投入更多内部推理，而不改动会话的整体设置，相当于一次临时的聚光。如果你是在一年多以前学的 Claude Code，要特别注意：「think」「think hard」「think more」这些老关键词如今不再被识别为特殊关键词，它们会被当作普通文本传递，因此对推理不再有任何影响。如果想要一个覆盖整个会话而非单个回合的设置，可以使用 /effort 命令，它会打开一个五档选择器（low、medium、high、xhigh、max）：遇到复杂的设计问题时切换到 xhigh，之后再降回 low，用于简单且更省成本的任务。

这个推理调节也可以常驻整个会话，通过快捷键 Option+T 启用（Windows/Linux 上是 Alt+T）。命令 /config 同样可以把这个设置固化下来。如果你会把工作交给子代理，还有个好消息：子代理会自动继承主对话的扩展推理设置，不需要在每次委派时重新配置。而且计划本身也不会不知所踪：设置项 plansDirectory 决定 Claude Code 把这些计划文件写到哪里，例如可以把它们纳入仓库版本管理，在代码评审时再读一遍。下面就来详细看看，这在你的日常实践中具体带来了什么变化。

实践练习

运行以下命令：

claude --permission-mode plan

然后提问：「ultrathink: 为这个 API 增加限流，请提出一套架构方案」。观察生成的计划，用「Yes, and use auto mode」批准它。在一个新会话中，对比 /effort low 和 /effort xhigh 在同一个问题上的表现，感受推理深度的差别。

解答 & 验证

「ultrathink」是如今唯一仍被识别的触发词，它能为单个回合临时触发更深入的推理，而不改变会话的努力级别。正是它促使 Claude 在你还没批准任何东西之前，就给出一份论证更充分的限流方案计划。用「Yes, and use auto mode」批准该计划之后，/effort low 与 /effort xhigh 的对比就能干净地把深度这一个变量单独隔离出来：/effort 会打开一个 5 档选择器（low、medium、high、xhigh、max）。在两个独立的会话中用这两档设置问同一个问题，就能感受到推理上的差距，而不会被「ultrathink」效应或对话历史干扰对比。

  • 在你回答计划结束时的提示之前，不会执行任何修改性命令：提示会停留在计划模式，给出类似「Yes, and use auto mode」的选项，而不是直接动手。
  • 选择「Yes, and use auto mode」之后，后续的工具调用不再逐条弹出确认框，说明会话确实已经切换到 auto 模式来完成后面的工作。
  • 在这两个新会话中，单独运行 /effort（不带参数）会显示当前生效的级别（先是 low，然后是 xhigh）；xhigh 下产出的计划应当明显比 low 下的更充实（步骤更多，架构选择的论证更多），这说明该设置确实改变了推理深度。
