03

命令 & Skills：将提示词工程化

从即兴提示词到版本化的流程

Vibe Coding 就是凭记忆一遍遍重打同一段提示词，每次都会有些出入。Skill 把这段提示词固化进一个纳入版本管理的 SKILL.md 文件：可复现、可通过 git 共享，审计则看它声明的 allowed-tools.

水平测试

如果一个命令还需要附带辅助文件（脚本、参考文档），应该放在哪里？

✓ 正确。目录形式的 .claude/skills/name/SKILL.md 除提示词之外还能附带支持文件，不同于单个的 .claude/commands/name.md.
→ 你已经掌握这一手，直接进入下一模块
✗ 不完全正确。答案是 .claude/skills/name/SKILL.md：斜杠命令的后继机制，可以附带辅助文件。

那段你反复重打的提示词：要是把它变成一个文件呢？

你有多少次几乎一字不差地重打同一段二十行的提示词，只为发起一次代码评审或生成一份变更日志？Vibe Coding 就是这样运作的：每次都临场发挥，指望能找回上周效果不错的那种说法。真正的问题不是懒，而是不稳定：漏掉一条要求、少一个例子，结果就变了，而你不知道为什么。一个命令或一个 skill 恰好解决这个问题：它把提示词一次性固化到文件里，之后每次敲对应的命令，都会原样重放。

具体来说，这个文件有两种形态，弄清谁源自谁很有用。第一种是早期做法，就是往下面这个目录里放一个普通的 Markdown 文件：.claude/commands/。它今天依然完全受支持，简单需求用它就够。第二种是 Skills，即一个 .claude/skills/name/ 目录，里面放一个 SKILL.md，这是官方推荐的后继机制，除提示词本身外还能附带辅助文件（脚本、参考文档）。两者后来已经合并：一个 .claude/commands/deploy.md 和一个 .claude/skills/deploy/SKILL.md 都会创建同一个命令 /deploy，行为完全一致。因此迁移到 SKILL.md 从来不是断裂式变更，只是多了一些能力。

但真正把固化的提示词变成团队工具的，是可以挂在它头部的那些配置。这个头部叫 frontmatter，写在提示词正文之前，描述这个 skill 该如何执行。字段 disallowed-tools 会在 skill 运行的整个期间，把某些工具从可用工具池里移除：比如可以避免在无人值守的自主循环中向用户抛出提问。字段 context: fork 更进一步：它让 skill 作为一个隔离的子代理运行，无法访问当前会话的历史。这种模式现在默认在后台执行，你可以在 skill 自行工作的同时继续做别的事。再加上字段 paths，它用 glob 模式把 skill 的自动触发限制在特定文件上，你得到的提示词就不只是可复现：它的作用范围也变得可审计、可预期。

这才是相比复制粘贴提示词的真正收益：对一套流程有权做什么、何时触发、对你有多大可见度的精细掌控。理解这些配置之后，skill 就不再只是一个顺手的快捷方式：它是一份团队流程，可以像仓库里任何其他文件一样版本化、评审和演进。下面具体看看它带来的变化。

✓ 正确。正确。从这个版本起，context: fork 的 skill 默认在后台运行（执行期间你可以继续工作），除非在它的 frontmatter 中设置了 background: false。

实践练习

创建 .claude/skills/resume-diff/SKILL.md，只写最小的 frontmatter（description, disable-model-invocation: true），正文注入下面这条命令，然后要求给出 3 条要点的摘要：

!git diff HEAD

用 /resume-diff测试，然后加上 context: fork 和 agent: Explore，让它作为子代理在后台运行。

解答 & 验证

只要创建 .claude/skills/resume-diff/SKILL.md，/resume-diff 就存在了。自从斜杠命令与 Skills 合并之后，放在 .claude/skills/name/ 下的 SKILL.md 文件确实会创建与普通 .claude/commands/name.md 相同的 /nom 命令，而且还能额外附带辅助文件。

接着在 frontmatter 里加上 context: fork 和 agent: Explore，这个 skill 就会作为隔离的子代理运行，无法访问对话历史，由 Explore 类型的代理执行。由于 fork 模式现在默认在后台执行，你会立刻拿回控制权，diff 摘要在后台生成，除非加上 background: false 回到阻塞式执行。

  • 文件创建后，/resume-diff 会出现在斜杠命令的自动补全菜单里，无需重启 Claude Code。
  • 加上 context: fork 和 agent: Explore 之后，运行 /resume-diff 会立刻把控制权交回提示行，任务会作为后台执行出现在 /tasks 列表里，而不是阻塞提示行。
  • 生成的摘要正好是 3 条要点，只涉及 git diff HEAD 中真正被修改的文件，不引用会话中更早的对话内容，这证明子代理是隔离运行、没有历史的。
