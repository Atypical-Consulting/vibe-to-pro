05

子代理：委派与并行

Agent 工具（原名 Task）

Vibe Coding 是一条什么都混在一起的线程：检索、写代码、跑测试、上下文不断膨胀。子代理把每个任务隔离开（独立上下文、受限工具，有时还有专属 worktree），并让你有意识地选择由哪个模型做哪件事。

→ 你已经掌握这一点，直接进入下一个模块

如果既能委派任务，又不丢失思路呢？

你一定遇到过这种时刻：一个 Claude Code 会话开始四处发散，你让它先找一个 bug，再写补丁，接着跑测试，然后又去读一个毫不相干的文件。过一阵子，上下文（模型「记住」的全部对话内容）被塞得太满，回答就不再精准。这正是 Vibe Coding 的典型症状：用一条对话线程扛下所有事情。解决办法不是在同一条线程里做得更快，而是把它拆开：把每个任务交给一个独立的子代理，它有自己的上下文，不会污染你的上下文。

具体来说，这套委派机制依赖一个 Claude Code 称为 Agent 的工具（它最初叫 Task）。默认情况下，子代理会继承所有可用工具（包括写文件和执行 Bash 命令），除非你在它的 frontmatter（定义该代理的文件顶部那段配置头）里用 tools: 或 disallowedTools: 明确加以限制。正因如此，你可以创建一个严格只读的代码审查代理：即使它想，技术上也破坏不了任何东西。你还可以用 isolation: worktree把隔离推得更远，它让子代理在一份独立的 git 副本中工作，这份副本从你的默认分支创建，如果不含任何修改就会被自动删除。这样就能放心实验，永远不碰你的主仓库。

但为什么每次只用一个子代理？这就轮到并行化登场了。/subtask 会启动一个仍然挂在当前会话上的子代理，可以在任务列表里看到；/fork则把整个对话复制到一个完全独立的后台会话中，适合在不阻塞当前工作的前提下尝试有风险的方案。只要你处于交互式会话，forking 默认就是开启的。为了避免委派层层升级、最终失控，这里有两道护栏：并行执行的子代理上限为 20 个（可通过环境变量 CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS调整，且整个会话没有总量限制），以及最多 3 层的嵌套深度。超过之后，Agent 工具会对除 fork 之外的所有子代理消失，以防某个子代理无限地再去启动别的子代理。

还剩一个问题：每个子代理由哪个模型驱动？你不必把一切都交给最强（也最贵）的模型。解析顺序依次是：调用时传入的参数，代理 frontmatter 中的 model: 字段（它也可以直接写成 inherit，表示沿用当前对话的模型），环境变量 CLAUDE_CODE_SUBAGENT_MODEL，最后才回退到主对话的模型。这样你就能有意识地把轻量模型分配给简单任务，把算力留给真正值得的地方。还有一个 memory: 字段，可以让子代理在多次执行之间拥有持久记忆，作用范围可以是用户级、项目级（推荐的范围，因为可以和代码一起版本化）或本机级。而要创建这样一个子代理，已经不需要专门的向导：用自然语言告诉 Claude 即可，或者直接编辑 .claude/agents/中的文件。下面就详细看看这具体带来了什么变化。

实践练习

请 Claude 创建一个名为 code-reviewer 的只读子代理（工具为Read, Grep, Glob），模型用 haiku。用这个代理运行 /subtask，并通过 /tasks观察它在后台的执行。然后加上 isolation: worktree，让它在一份隔离的 git 副本中工作，最后用一条权限规则把它挡住：permissions.deny: ["Agent(code-reviewer)"].

解答 & 验证

把工具限制为 Read、Grep、Glob 之所以有效，是因为子代理默认会拿到所有可用工具，包括写入和 Bash，除非通过 frontmatter 的 tools: 或 disallowedTools: 字段显式限制。正是这条声明 tools: Read, Grep, Glob 让它变成严格只读。随后加上 isolation: worktree，它就会在一份隔离的 git 副本中运行，该副本从默认分支切出，若没有任何修改则自动清理，完全不触及主仓库。练习的最后一步是用一条权限规则明确阻止这个子代理，形如 permissions.deny: ["Agent(code-reviewer)"]，写在 settings 中。

  • 在 /tasks 里，code-reviewer 子代理的条目从「Working」变为「Completed」，而它的工具记录中没有出现任何 Edit、Write 或 Bash 调用（只有 Read、Grep、Glob）。
  • 加上 isolation: worktree 之后，执行期间会出现一个新的 worktree（用 git worktree list 可以看到），如果没有文件被修改，结束时它会自行消失。
  • 添加 permissions.deny: ["Agent(code-reviewer)"] 规则之后，再尝试调用这个特定的子代理时会被明确拒绝，并给出权限被阻止的提示，而不再像之前那样执行。
