后台 & 多代理工作流

扩大规模而不失控

在 Vibe Coding 中，你发出一个 prompt，却不知道有多少个代理在运行，也不知道怎么停下它们。掌握后台任务和工作流，就是清楚知道谁在做什么，并为规模与跨会话权限设置护栏。

水平测试

默认情况下，一个 Workflow 最多能并发运行多少个代理？

✓ 正确。最多 16 个并发代理，整个 workflow 执行期间的总上限是 1000 个代理。
→ 你已经掌握这一手段，直接进入下一个模块
✗ 不完全正确。是 16：超过之后，多出来的调用会排队等待空位释放。

如果 Claude 能在你关掉电脑之后继续工作呢？

在 Vibe Coding 中，你多半已经养成了这样的习惯：发一个 prompt，等回复，再发一个。整个会话跑在同一条线程里，就在你眼前，你一关终端它就停了。但如果你想让 Claude 并行探索三条思路，或者在你吃午饭时继续做审计呢？这正是后台会话的用武之地：这样启动的任务会继续运行而不占住你的屏幕，一个专门的视图（claude agents）按状态（等待输入、进行中、已完成）汇总所有这些会话，让你随时知道谁在做什么，而不必让每个窗口都开着。

尝过甜头之后，人很容易想成倍扩大：为什么不让几十个代理同时在同一个项目上干活呢？这正是 Workflow tool 的职责：它可以在后台编排数以百计的代理，并用简单的原语来组织：单独启动一个代理、并行启动多个，或者把它们串成流水线。但一个能在无人直接监督下调动如此多资源的系统需要护栏：没有上限，一个没规划好的 workflow 几分钟内就可能拖垮你的机器或耗光你的 API 预算。因此，专门针对 Workflow tool（这个限制不同于前面提到的简单委派给子代理的限制），默认存在同时最多 16 个活跃代理的上限（超过之后，新的调用会排队等待），每次执行的总上限为 1000 个代理。还有一条规模指令把口子收得更紧，默认把 workflow 控制在 15 个代理以内，而不像以前那样让规模完全放开。

扩大规模而不失去控制，不只是限制代理的数量：还要能像对待普通进程那样，逐个地操作它们。一个后台会话可以被重新接管、通过日志查看、干净地停止、重新启动或删除：相当于一套完整的生命周期，这样就不会有你不知情的幽灵任务在跑。而当多个会话在同一个项目的相关部分上工作时，它们之间甚至可以互相通知，包括只要在你的 prompt 里提到其中一个即可：你不需要自己去编排通信，Claude 会处理。一个监控工具补全了这幅图景，它以流式方式跟踪后台脚本里发生的事情，同时完全不会暂停你的对话。

还剩最后一个问题：如果没人在旁边告诉它，怎么知道一个后台代理该在什么时候停下？这就是任务结束条件的作用，你用自然语言把它表述出来：Claude 会持续进行多个回合，一个小模型在每一步评估条件是否满足，直到自动停止。同样的受控自主原则也体现在周期性任务上：安排一个 prompt 按固定间隔重复执行，同样带有每个会话的上限，以免悄悄堆积起被遗忘的任务。下面就来详细看看这在实际中带来了什么改变。

运行以下命令，在后台启动一次审计：

打开 claude agents，用 Ctrl+T 固定该会话，然后用 claude logs <id> 查看它的日志。接着在一个小任务上测试下面的命令，看 Claude 如何自行循环直到条件满足：

解答 & 验证

运行以下命令会创建一个后台会话：

claude --bg "审计仓库中的 TODO"

全屏视图 claude agents 按状态（Needs input / Working / Completed）汇总会话，便于找到并固定正确的那个会话。命令 claude logs <id> 属于同一组子命令，其中还包括 attach, stop, respawn 和 rm，它们共同覆盖了一个后台会话的完整生命周期：因此它可以在不中断会话的情况下查看日志。下面的测试之所以有效，是因为这条指令定义了一个任务结束条件，Claude 会借助一个小模型逐轮重新评估，直到判定条件已达成：

/goal 所有测试通过且 lint 干净
  • 在 claude agents 中，一旦 TODO 审计完成，会话会从「Working」状态变为「Completed」，并且按下 Ctrl+T 后固定图标会一直可见。
  • claude logs <id> 会返回该会话的输出流（在 repo 中找到的 TODO 列表），而不会出现「找不到会话」之类的错误信息。
  • 执行 /goal 所有测试通过且 lint 干净 之后，对话会连续进行多个回合，无需你再次输入，直到出现一条确认条件已达成的最终消息；在此之前你也可以用以下命令中断循环：/goal clear.
