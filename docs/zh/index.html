00 · 现状

一个能跑通的 prompt，不等于一套工程实践。

Vibe Coding 能产出结果，却没有任何保障：没有权限范围，没有可追溯的记录，出错时也没有安全网。下面是同一个诉求的两种处理方式。

Vibe Coding
$ claude
> 修复登录的 bug
…修改了 4 个文件，没有任何 review
✓ 「看起来能用」
✗ 直接 push 到 main
专业实践
$ claude --permission-mode plan
> 修复登录的 bug
→ 已给出计划 · 3 个文件 · 2 个测试
✓ /code-review high --fix
✓ /commit-push-pr → PR #142
01 · 方法

未经核实，绝不写入课程。

本课程不是凭记忆写成的。每条事实在成为课程中的一行之前，都要走完同一条流程：

1

提取

官方 CHANGELOG 的 385 个版本被逐一拆分和审阅，从中筛选出重大功能，而不是细枝末节的修复。

2

核实

每一项候选功能都通过一次专门的检索，独立对照 code.claude.com 上的最新文档。

3

裁定

每条事实都会得到一个结论: 已确认, 已更新 （此后行为已发生变化），或 无法核实.

4

舍弃或发布

只有已确认或已更新的事实才会进入课程，并注明来源。其余一律舍弃，绝不当作既定事实呈现。
