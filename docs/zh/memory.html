02

记忆：CLAUDE.md 与自动记忆

不再每次会话都从头解释一遍

在 Vibe Coding 中，每次会话都从零开始：同样的约定、同样的修正要一再重复。掌握 CLAUDE.md 与自动记忆，就能把这种易失的上下文变成有版本管理、可在团队中共享、并可审计的配置，审计手段就是 /context.

水平测试

Claude Code 的自动记忆会记录多少种类型的笔记？

✓ 正确。4 种类型：user （偏好），feedback （已确认的修正），project （无法从代码推断的上下文），reference （在哪里找到外部信息）。
→ 你已经掌握这一手段，直接进入下一个模块
✗ 不完全正确。答案是 4：user, feedback, project, reference.

为什么你总是要向 Claude 重复同样的指示？

你多半经历过这种情况：打开一个新会话，一切都得重新解释一遍：该用哪个包管理器、团队内部的命名约定、上周你在遗留代码里发现的那个坑。这些都没有被记住：每次会话都以空白的上下文重新开始，就像 Claude 从来没有了解过你的项目。这很烦人，但更重要的是方法问题：那些一次次口头说明的内容，应该变成写下来的配置，有版本管理、与团队共享、可以审计，而不是消失在某次对话的历史记录里。

为此的第一个工具，就是项目根目录下的 CLAUDE.md 文件：一份 Claude 每次启动都会重读的常驻备忘。你甚至可以用导入语法（@path/to/file.md）让它指向其他文件，最大深度为 4 跳，以避免无止境的导入链；反过来，如果你想阻止某个路径被自动加载，只需用反引号把它包起来（`@README`）。一个实用但很能说明系统逻辑的小细节：你还可以在这个文件里放 HTML 注释，给之后阅读它的人留言。它们会在注入会话上下文之前被移除，因此不消耗任何 token，同时如果有人直接打开文件，仍然能看到它们。

但如果你是在任务过程中纠正 Claude，而不是提前在 CLAUDE.md 里写好规则，会发生什么？这时默认开启的自动记忆就派上用场了：它把会话中发生的事情记成笔记，分为 4 类：你的偏好（user）、你已确认的修正（feedback）、无法从代码推断的项目专有上下文（project）、以及指向外部信息的指针（reference）。只要用自然语言说「记住…」就能触发一次记录；这些笔记默认存放在按项目划分的目录中，你可以通过参数 autoMemoryDirectory把它移到别处；如果你更愿意全部手动管理，也可以通过 /memory 或变量 CLAUDE_CODE_DISABLE_AUTO_MEMORY=1 关闭整个机制。

为什么要费这个劲，而不是让上下文每次重建？因为一份只增不减、从不清理的记忆，很快就会和没有记忆一样碍事：CLAUDE.md 不断膨胀，塞满了 Claude 本来就能从代码本身推断出来的信息。正因如此，/doctor 可以替你做筛选：它会找出与代码重复的部分，保留那些陷阱和非标准约定，建议把其余内容迁移到 skills 或嵌套的 CLAUDE.md，并且没有你的明确确认就不会做任何改动。这份积累下来的记忆也不只对你自己有用：/team-onboarding 会基于它生成一份面向新队友的上手指南。下面就具体看看，这带来了什么改变。

如何阻止路径 @path/to/file.md 在 CLAUDE.md 中被自动导入？

✓ 正确。正确。用反引号包裹路径（@README）会阻止它被自动导入；不加反引号时，@path/to/file.md 这样的路径会被正常导入，最大深度为 4 跳。
✗ 不完全正确。不太对。真正阻止导入的，是在路径两侧使用反引号（@README）：HTML 注释和跳数深度都起不到这个作用。

CLAUDE.md 加载进上下文时，其中的块级 HTML 注释（<!-- … -->）会怎样？

✓ 正确。正确。块级 HTML 注释会在注入上下文之前被移除（因此不消耗 token），但直接打开文件时仍然可读，所以可以用它们写给人看的注解。
✗ 不完全正确。不完全正确。这些注释不会被注入上下文：它们在加载前就被移除了，同时如果直接打开 CLAUDE.md 文件，仍然可以看到它们。
实践练习

运行 /init 生成一份基础的 CLAUDE.md，加入一条明确的规则（「使用 pnpm，绝不用 npm」），然后在任务过程中故意就某个偏好纠正 Claude。用 /memory 确认这次纠正确实被记入了自动记忆，再用 /context确认它已被加载，最后运行 /doctor，看看它是否建议为你的 CLAUDE.md 瘦身。

解答 & 验证

在任务过程中对 pnpm 偏好所做的纠正，会被记为 feedback 类型的笔记，这是自动记忆记录的 4 种类型之一（另外还有 user、project 和 reference），用来追踪已确认的修正。这条笔记应该能在 /memory 中看到，也应该出现在 /context 列出的本次会话已加载来源中。

最后走一遍 /doctor，依据的是它会建议对照代码给 CLAUDE.md 去重，同时保留像 pnpm 规则这样的陷阱和非标准约定。它会把其余内容迁移到 skills 或嵌套的 CLAUDE.md，但只有在用户明确确认之后才会动手，绝不会悄悄进行。

  • /memory 显示一条新的 feedback 类型条目，对应 pnpm 那次纠正，与已有的 user/project/reference 笔记区分开。
  • /context 在已加载的来源中列出一个位于 ~/.claude/projects/<projet>/memory/ 下的文件，并把它的 token 大小计入显示的总量。
  • /doctor 会先给出它对 CLAUDE.md 的判断（哪些因为可以从代码推断而建议移除，哪些作为非标准陷阱予以保留），并在做任何修改之前等待确认。没有这一步，不应该发生任何文件改写。
