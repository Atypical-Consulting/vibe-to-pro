终章：实践者检查清单 & 参考来源

十二个杠杆，只有一个目标：不再依赖运气。下面这份检查清单是本课程的总结。在宣称某个 Claude Code 项目「可以上生产」之前，请先逐项确认。

实践练习

重新打开你的 练习仓库（模块 01），把三个已经练习过的杠杆组合成一套连贯的配置：(1) 启用沙箱，并配置一条 sandbox.credentials.files 规则（见「控制 & 安全」模块），(2) 一个 PreToolUse hook，用于拦截未经确认的 rm 操作（见 Hooks 模块），(3) 在一个独立的 claude --worktree 中打开会话（见「Git & worktrees」模块）。在这个 worktree 中启动一次会话，确认三重保护同时生效：这正是下面这份检查清单所描述的 .claude/ 配置，而不是三项孤立设置逐个测试的结果。

专业实践者检查清单

  • 凡是涉及密钥或生产环境的项目，都启用了 Bash 沙箱和网络规则。
  • .claude/settings.json（权限、hooks）已纳入版本控制，并像代码一样接受评审。
  • CLAUDE.md 记录的是陷阱和非标准约定，而不是 Claude 从代码里就能推断出来的内容。
  • 重复性任务写进受版本控制的 skills，而不是留在敲 prompt 的人的脑子里。
  • 高风险任务先走计划模式，再执行。
  • 子代理拥有明确的工具范围（tools:/disallowedTools:），而不是默认的全量访问权限。
  • 关键校验（lint、测试、密钥扫描）由 hooks 保证，而不是靠期望。
  • 每个外部 MCP 服务器在批准前都经过评审，团队维护一份允许清单。
  • /rewind 和 worktrees 是在共享代码上做高风险试验前的条件反射。
  • 多代理工作流有一个明确设定的 workflowSizeGuideline，而不是「跑起来看看再说」。
  • 已安装的插件按 SHA 锁定，其 token 成本也是已知的 (claude plugin details).
  • CI 集成使用 --bare、--output-format json 输出以及明确的权限，在共享流水线中绝不使用 --dangerously-skip-permissions。

综合测验

快速测验 · 控制

相比 bypass 模式下的会话，--restricted 标志具体做了什么？

✓ 正确。正确。--restricted 移除命令执行工具和 WebFetch，把文件工具限制在工作目录内，并拒绝 bypass 模式；这个选择在会话进行中无法取消。适合用于打开不可信的仓库，或让新手在没有逃逸沙箱风险的情况下做实验。
✗ 不完全正确。不完全正确：--restricted 做的远不止切断网络或普通的 manual 模式，它还会移除命令执行工具和 WebFetch，把文件访问限制在工作目录内，并禁止在会话期间退回 bypass 模式。
快速测验 · 记忆

如何防止 @path/to/file.md 这样的路径被自动导入到 CLAUDE.md 中？

✓ 正确。正确。用反引号包住路径（@README）就能阻止其自动导入；不加反引号时，@path/to/file.md 这样的路径会被正常导入，最大深度为 4 层。
✗ 不完全正确。不完全正确。真正阻止导入的是给路径加上反引号（@README）：HTML 注释和跳转深度都起不到这个作用。
快速测验 · Skills

SKILL.md 的 frontmatter 中，disallowed-tools 字段有什么作用？

✓ 正确。正确。disallowed-tools 会在 skill 执行期间缩小可用工具池。比如可以用它在无人应答的自主循环中禁用 AskUserQuestion。
✗ 不完全正确。在 skill 运行期间把某些工具从可用池中移除的是 disallowed-tools，典型用途是在无人应答的自主循环中禁用 AskUserQuestion。
快速测验 · 计划

在 Claude Code 的 settings.json 中，哪个参数决定计划模式把计划文件写到哪里？

✓ 正确。正确。plansDirectory 参数决定计划模式把计划文件写到哪里，它相对项目根目录解析，因此很适合把这些计划纳入仓库版本控制，并在 PR 评审时复看。
✗ 不完全正确。不完全正确。是 plansDirectory，相对项目根目录解析，便于把生成的计划纳入版本控制并在评审中复看。
快速测验 · 子代理

默认情况下，Claude Code 在一次会话中最多可以并行运行多少个子代理？

✓ 正确。正确。默认上限是 20 个并发子代理，可通过环境变量 CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS 调整；而每次会话的总量上限已在 v2.1.224 中取消。
✗ 不完全正确。不完全正确。默认上限其实是 20 个并发子代理，可通过 CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS 调整。
快速测验 · Hooks

根据 hooks 文档，哪个事件会在上下文压缩之前触发，并且可以用退出码 2 阻止压缩？

✓ 正确。PreCompact 在压缩之前触发，可以用退出码 2 阻止压缩。PostCompact 则只在压缩之后才触发，这一机制适合用来在重要信息被压缩前将其归档。
✗ 不完全正确。是 PreCompact：它在压缩之前介入，可以用退出码 2 阻止压缩。PostCompact 在压缩已经完成之后才触发，来不及阻止压缩。
快速测验 · MCP

根据文档，新建 MCP 服务器目前推荐使用哪种传输方式？

✓ 正确。正确。只要条件允许都推荐使用 HTTP streamable 传输；SSE 仍受支持，但文档中已明确标记为废弃。
✗ 不完全正确。不完全正确。推荐的是 HTTP streamable：SSE 仍受支持，但已被标记为废弃。
快速测验 · 检查点

/rewind 菜单中的「Summarize up to here」选项具体做什么？

✓ 正确。正确。「Summarize up to here」只作用于对话历史：它压缩所选时间点之前的内容，不修改磁盘上的文件。这有助于在不丢失已完成代码工作的前提下释放上下文。
✗ 不完全正确。不完全正确。这个选项既不碰任何文件，也不创建 commit：它只压缩所选时间点之前的对话，代码保持原样。
快速测验 · Git

在没有特别配置的情况下，Claude Code 新建的 worktree 默认从哪个引用开始？

✓ 正确。正确。自 v2.1.133 起 worktree.baseRef 默认为「fresh」：每个新建的 worktree 都从 origin/<默认分支>开始。「head」设置（需显式启用）则从你的本地 HEAD 出发，包含未推送的 commit。
✗ 不完全正确。不完全正确。默认值是「fresh」：它从 origin/<默认分支>开始。「head」也存在，但需要自己启用，才能从带有未推送 commit 的本地 HEAD 出发。
快速测验 · 后台

CronCreate/CronList/CronDelete 工具每次会话最多可以计划多少个循环任务？

✓ 正确。正确。CronCreate/CronList/CronDelete 工具每次会话的上限是 50 个循环任务；而 /loop 则是在当前对话中按固定间隔直接执行一个 prompt 或一个 skill，不受这个上限限制。
✗ 不完全正确。不完全正确。答案是 50：Cron 工具（CronCreate/CronList/CronDelete）把每次会话计划的循环任务数限制在这个数量，这一点要与运行在当前对话中的 /loop 区分开。
快速测验 · 插件

对于 github/url/git-subdir 类型的插件来源，marketplace.json 中的哪个字段可以锁定插件的确切版本，不受该分支后续 commit 的影响？

✓ 正确。正确。sha 字段（一个完整的 git commit）锁定插件的具体版本，不受所引用分支上后续推送的 commit 影响。
✗ 不完全正确。不完全正确。锁定确切版本的是 sha 字段（一个完整的 git commit），不受该分支后续 commit 的影响。这个用途既没有 version 字段，也没有 tag 字段。
快速测验 · SDK、CI/CD、IDE

在哪种情况下，SDK 的 fallbackModel 机制永远不会切换到备用模型？

✓ 正确。正确。fallbackModel 最多接受三个模型并按顺序尝试，但只在过载或服务器错误时生效，身份认证、计费或速率限制错误永远不会触发切换。
✗ 不完全正确。不完全正确。过载和服务器错误确实会触发切换；恰恰是身份认证、计费或速率限制错误永远不会启用 fallbackModel。
