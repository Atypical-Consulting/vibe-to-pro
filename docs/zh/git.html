Git、worktrees & PR 自动化

多人并行协作，互不冲突

Vibe Coding 会在代码进入共享仓库的那一刻失效：没有 worktrees，也没有 Git 纪律，就会覆盖别人的工作，或者推送未经评审的 commit。worktrees 与 PR 自动化让多个代理并行运行而互不碰撞，同时留下干净的记录。

✓ 正确。自 v2.1.229 起，危险标志（--force, --amend, --no-verify）不再由 /commit-push-pr 自动批准：工作流的其余部分仍然保持自动化。
→ 你已经掌握这一手段，跳到下一个模块
✗ 不完全正确。它会重新要求确认，因为 /commit-push-pr 自 v2.1.229 起不再自动批准危险的 git/gh 标志。

多个代理，一个仓库：如何避免连环相撞？

你多半已经这样做过：让 Claude Code 处理一项任务，然后在它还在跑的时候又开了第二个窗口，让它去修别的东西。结果就卡住了：两个会话在同一个分支上修改同一批文件，其中一个最终覆盖了另一个的成果。这不是 bug，而是传统 Git 仓库的必然结果：磁盘上只有一份工作副本，所以同一时刻只能有一个代理安全地动它。那么问题来了：怎样才能在同一个项目上并行运行多个代理，又不用在分支之间玩抢椅子游戏？

答案藏在一个早已存在却常被忽略的 Git 工具里：worktree。一个 worktree 就是同一个仓库的第二份工作副本，放在另一个目录中，但共享同一份 Git 历史：它不是完整的克隆，只是一个独立的分支，可以随意修改而不触碰主分支。Claude Code 直接建立在它之上：使用 --worktree 或 -w 标志会在 .claude/worktrees/<name>/ 下创建这个隔离目录，并新建一个名为 worktree-<name> 的分支，因此在其中启动的代理根本不可能覆盖另一个代理在别处所做的工作。还剩一个问题：这块新工地从哪里开始？默认情况下，它从 origin/<默认分支> 开始，那是一个干净且最新的基线；但如果你已经有未推送的本地工作想要延续，就必须显式启用从本地 HEAD 出发的那个选项。

Vibe Coding 的第二个摩擦点出现在任务收尾：代码写完之后，还得 commit、push、开一个 pull request（向主分支发起的合并请求，通常在被接受前会经过评审）。而恰恰就是在这里，人们会漏掉一步，或者出于习惯直接推到主分支上。Claude Code 把这套机械动作自动化了：在 worktree 里后台工作的代理会在结束前 commit 并 push 自己的成果，只有在任务确实需要时才开一个草稿 pull request，同时遵守你写在 CLAUDE.md 里的 Git 指令。但自动化不等于放任不管：在这套 commit、push 和 pull request 的工作流中，那些可能造成难以挽回破坏的标志（强制 push、修改已有 commit、绕过校验 hook）不再被自动执行，而是会重新要求一次明确的确认。换句话说，自动化替你省掉重复的苦差事，但没有替你对风险动作拍板。

最后一个细节对日常影响很大：同一个仓库下的所有 worktrees 共享同一套配置（CLAUDE.md、权限设置、自定义代理、Skills、自动记忆），所以每开一块并行工地都不必重新复制一遍。而为了不用每次都打开 GitHub 就能掌握全局，与当前分支关联的 pull request 状态会以一个彩色小圆点的形式显示在界面里。下面就来看看它们具体带来了什么变化。

实践练习

运行下面的命令来启动一个隔离的会话：

claude --worktree essai-pro

修改一个文件，在 commit 之前先运行 /code-review high --fix 接着运行 /commit-push-pr。检查一下 git push --force 不会被自动批准，并把 worktree.baseRef: "head" 加入 .claude/settings.json.

解答 & 验证

claude --worktree essai-pro 会在 .claude/worktrees/essai-pro/ 下创建一个隔离的 worktree，位于新分支 worktree-essai-pro 上，这样就可以修改文件而不触碰当前的工作分支。文件 commit 之后，由 /commit-push-pr 负责推送这份工作并开启 PR。自 v2.1.229 起，遇到危险标志它不再静默执行：一次 git push --force 会重新要求确认，而不是被自动批准。若想让这个 worktree 以及之后新建的 worktrees 从本地 HEAD 开始，包含未推送的 commit，而不是从 origin/<默认分支> 开始，就需要显式地把下面这段配置加入 .claude/settings.json:

{
  "worktree": { "baseRef": "head" }
}

这就是本练习期望达到的最终配置。

  • 目录 .claude/worktrees/essai-pro/ 存在，并且在其中运行 git branch --show-current 返回 worktree-essai-pro。
  • 在这个 worktree 里通过 /commit-push-pr 尝试 git push --force 时，会出现一次明确的确认提示，而不是直接执行推送。
  • 编辑之后 .claude/settings.json 中包含 "worktree": { "baseRef": "head" } 这个键，并且随后新建的 worktree 头部 commit 与当前本地分支一致，而不是 origin/<默认分支>).
